# Taskkorb iOS STT: WhisperKit vs whisper.cpp vs SpeechAnalyzer

Research only. **No product code in this change.** Written 26 Aug 2026.

**Sources:** official GitHub raw files and GitHub API for Argmax / ggml-org; official Apple documentation markdown (`developer.apple.com/documentation/….md`) and WWDC25 session 277 page. Firecrawl CLI is installed in this environment but **unauthenticated**; the keyless tier was rate-limited after earlier scrapes, so this memo does not claim a fresh Firecrawl pass of these three pages. An earlier Firecrawl scrape of the Speech framework index is already in `.firecrawl/apple-speech.md` (gitignored).

This is **not legal advice**. Licenses and availability change.

## v1 pick

**Ship WhisperKit** (the `WhisperKit` product in [argmaxinc/argmax-oss-swift](https://github.com/argmaxinc/argmax-oss-swift); `https://github.com/argmaxinc/WhisperKit` redirects there).

Taskkorb iOS v1 is: open the app → tap Talk → on-device transcript → Share/Copy **text** (not audio). That is already the cowork-platform constraint. WhisperKit is the only option of the three that is all of: MIT, Swift Package, official iOS sample, documented on-device, and **not** gated on iOS 26/27.

Do **not** pick whisper.cpp as the v1 integration. Official iOS samples exist and are on-device, but they are XCFramework + C/Obj-C demos, not a Swift package you add in one step.

Do **not** pick SpeechAnalyzer as the **only** v1 path. It is the right first-party API on iOS 26+, and Apple’s own docs say its transcriber modules do not send voice audio to Apple. It is still wrong as the sole floor: API is iOS 26, live-capture helper in the current sample is iOS 27, SpeechTranscriber has extra hardware/locale gates, and Hindi is not listed in the spoken WWDC transcript (slide-only). Revisit as an **iOS 26+ optional path** after Talk works.

## What each official page actually says

### WhisperKit / Argmax OSS

- GitHub API (26 Aug 2026): `argmaxinc/WhisperKit` → `argmaxinc/argmax-oss-swift`, license SPDX `MIT`, description “On-device Speech AI for Apple Silicon.”
- README: WhisperKit, SpeakerKit, TTSKit are separate products in one package. Pro SDK is a **different** paid product (realtime speakers, custom vocab, Android). v1 uses the OSS `WhisperKit` product only.
- `Package.swift` platforms: iOS 16, macOS 13, watchOS 10, visionOS 1.
- Live mic is demonstrated via CLI `--stream` and the WhisperAX app, not only file `transcribe(audioPath:)`.

### whisper.cpp

- README supported platforms includes a checked **iOS** link to `examples/whisper.objc`.
- Two first-party mobile samples: Obj-C and SwiftUI. Both require `./build-xcframework.sh` first.
- Core ML support is **encoder-only**; “the decoder which is in the ggml model is still required.”
- XCFramework section documents a Swift `binaryTarget` zip from GitHub Releases.

### SpeechAnalyzer

- Availability in the official `.md` front-matter: iOS / iPadOS / Mac Catalyst / macOS / tvOS / visionOS **26.0+**.
- Role: hold modules, accept audio, control the session. Typical module: `SpeechTranscriber(locale:preset: .transcription)`.
- Assets: `AssetInventory.assetInstallationRequest(supporting:)` then `downloadAndInstall()`.
- WWDC25 277 (Apple page transcript): new API in **iOS 26**; “we wanted to keep speech private. Our new, on-device model achieves all of that.” Model is system-stored and auto-updated. Not on watchOS. Hardware requirements apply. DictationTranscriber is the fallback for unsupported language or device.
- Official privacy split: SpeechAnalyzer transcriber modules **do not** send voice audio to Apple; `SFSpeechRecognizer` **does** (unless you force on-device).

## Why this is the Taskkorb v1 pick

Existing product constraint ([cowork-platform memo](2026-08-26-cowork-platform.md)): iOS v1 is Talk + Share, no overlay, no custom wake word, send **text**. Green-team web already cares about Hindi chrome.

1. **SwiftUI-shaped.** One SPM product and a Swift API. whisper.cpp’s official iOS story is still “build an XCFramework, then drop model files into the demo target.”
2. **On-device without iOS 26 as the floor.** A new Taskkorb Xcode app can still choose min iOS 17 to match WhisperAX, or 16 to match the package. SpeechAnalyzer cannot ship Talk to an iOS 25 phone.
3. **Multilingual is in the official model table**, including a recommended iOS large-v3 compressed variant. Apple’s SpeechTranscriber language list is not in the spoken WWDC transcript; Hindi must be proven at runtime if we take that path later.
4. **Licensing is shippable.** MIT SDK + MIT Core ML repo + MIT upstream Whisper. Include `LICENSE` + `NOTICES` (Apache-2.0 attribution for vendored swift-transformers).
5. **Later upgrade is additive.** On iOS 26+, SpeechAnalyzer + SpeechTranscriber is the zero-IPA-weight, first-party path with an official “modules don’t send audio” sentence. Use it when `SpeechTranscriber.isAvailable` and the locale is in `supportedLocales`. Keep WhisperKit as the fallback, not the other way around, until that matrix is measured on real devices.

### v1 implementation notes (not done in this change)

- Min iOS: **17** unless there is a measured need for 16 (WhisperAX is 17).
- First-run: download `tiny` or `base` for bring-up; do not block Talk on the 626 MB large-v3 fetch.
- Info.plist: `NSMicrophoneUsageDescription` only for this path. Orange system mic indicator. Do not start the mic at launch.
- Do not add TTSKit / SpeakerKit / Argmax Pro for v1 Talk.
- After transcript: Share/Copy text. Backend (if any) gets text, not audio.

### Open questions (cannot close from these official pages)

- Exact SpeechTranscriber locale list (including Hindi) — runtime `supportedLocales` or the WWDC slide, not the spoken transcript.
- Whether SpeechTranscriber hardware gates exclude the phones Taskkorb cares about.
- App Review treatment of a large on-demand Core ML download vs a bundled tiny model.
- Argmax Pro vs OSS if we later want their “realtime with speakers” claims — that is a different license.
